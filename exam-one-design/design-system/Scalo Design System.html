Stack & theming

There is no bespoke design system — daisyUI 5 is the system, unmodified. No custom theme is registered, no brand palette is overridden, no font family is configured. Everything inherits daisyUI defaults, which is why the whole template retint by swapping one attribute.

Framework
Nuxt 3 + Vue 3, <script setup lang="ts"> only
CSS
Tailwind 4 via @tailwindcss/vite
Components
daisyUI 5 as a Tailwind plugin — @plugin "daisyui"
Themes
All 32 stock themes registered; darkTheme: "dark"
Theme switch
@nuxtjs/color-mode writing data-theme on <html>
Icons
nuxt-icon + Lucide — <Icon name="lucide:user" size="20px"/>
Typeface
Not configured — Tailwind's default sans stack

One custom utility exists, in app.css: .dark-invert applies filter:brightness(0) invert(1) under twelve named dark themes, so monochrome brand SVGs (Google, GitHub, Apple, X) flip to white without a second asset.

/* app.css */ @import "tailwindcss"; @plugin "daisyui"; @import "./scalo-tw.css"; @custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));

Role assignments observed

  • primary CTAs, eyebrows, active nav, current plan
  • error destructive actions, logout, danger zone, validation
  • warning attention states, star ratings, deactivate
  • success 2FA enabled, selected-plan check
  • secondary upgrade CTA only

Tint conventions

  • bg-primary/10 — icon chip fill
  • bg-primary/5 + border-primary/40 — dashed invite cards
  • bg-error/10 + border-error/20 — alert + danger container
  • bg-error/5 → hover:bg-error/10 — delete row

Muting is done with the token's alpha channel rather than a gray: /80 emphasis body, /75 long-form, /70 default body, /65–/60 meta and labels. Bare opacity-60 appears in settings and is the older form of the same idea.

Buttons

Size by context

Settings pages use btn-sm almost exclusively — dense admin surfaces. Auth and company pages use the default height, and auth CTAs are always full-width.

The soft variant

btn-soft marks secondary-destructive or pending actions — "Remove", "Change Password", "Connecting…". Solid btn-error is reserved for the real commit.

Auth CTA btn btn-primary w-full gap-2 + lucide:arrow-right, :disabled="!isFormValid" Settings save btn btn-sm btn-primary Destructive btn btn-sm btn-error (soft variant = one step back) Social icon btn btn-ghost btn-square border border-base-300

Form fields

The signature pattern of this template: the input class is on a wrapping label, not the input. The icon and any trailing button are siblings of a borderless input.grow. Copy this exactly — it is used on every form in the repo.

<div class="form-control"> <label class="label pb-1" for="email"><span class="label-text">Email Address</span></label> <label class="input input-bordered flex items-center gap-2 w-full"> <Icon name="lucide:mail" size="20px" class="opacity-70" /> <input v-model="email" class="grow" @blur="validateEmailField" /> <!-- optional: btn btn-xs btn-ghost btn-circle --> </label> <label v-if="emailError" class="label"> <span class="label-text-alt text-error">{{ emailError }}</span> </label> </div> Field grid: grid grid-cols-1 gap-4 md:grid-cols-2

Checkbox, toggle, select

Preference lists are plain flex items-center gap-3 rows in a two-column grid — no card, no divider per row. checkbox-primary is used only for the auth terms agreement; settings checkboxes stay neutral. A toggle (not a checkbox) marks a setting that takes effect immediately.

Social row

Four square ghost buttons, always Google · Apple · GitHub · X in that order. Icons are w-5 h-5 except X at w-4 h-4, and all carry dark-invert.

Validation contract

A single composable backs every form. Each validator returns { valid, error }; pages hold one ref per error, validate on @blur, and gate the submit button on a computed.

useFormValidation() validateEmail(email) required + /^[^\s@]+@[^\s@]+\.[^\s@]+$/ validatePassword(password) required + min 8 characters validateRequired(value, field?) non-empty after trim, field defaults to "This field" Page shape: ref per field · ref per error · @blur validator · computed isFormValid → :disabled="!isFormValid" on the submit button

Worth knowing: isFormValid also requires the terms checkbox on login and register, so the CTA stays disabled until it is ticked. Verify overrides the generic check with an exact-six-digits rule.

Rules to follow when extending

Code

  • Always <script setup lang="ts"> — never Options API
  • No <style scoped> — Tailwind utilities only
  • Components auto-import; never write import statements for them
  • <NuxtLink> for internal links, never <a href>
  • Components PascalCase, pages kebab-case, composables useX.ts

Design

  • Semantic tokens only — no hex, no gray-500
  • Mute with text-base-content/NN, not a gray token
  • Page floor base-200, surfaces base-100
  • Radius grows with element size
  • Content data lives in constants/, not in templates
  • New routes get an entry in constants/nav.ts

Gaps & inconsistencies found

Things to decide on before reusing these patterns for Exam.one, rather than copying the drift forward.

Label

label + span.label-text on auth pages vs bare fieldset-label on settings/profile, with settings/account mixing both. Pick one.

Muting

text-base-content/60 and bare opacity-60 are used interchangeably for the same section labels — the second also fades borders and icons.

Active

Sidebar Profile uses active bg-base-200; Account, Notification, and Manage Plan use only active, so the current page renders differently by route.

Routes

Auth lives under /account/* but the settings account page is /settings/account; the sidebar links Manage Plan as /settings/manage-plan while nav uses /settings/plan (redirected in config).

Missing

2FA is a PlaceholderSoon stub, yet settings/account advertises an "Enable 2FA Authentication" row that goes nowhere. If Exam.one needs 2FA, it is a net-new design.

Hardcode

The sidebar's links, avatars, and account switcher are hardcoded, and settings state is local refs only — no store, no persistence. Real wiring is entirely ahead of us.

A11y

Feature rows and danger-zone rows are divs with cursor-pointer — not focusable or keyboard-operable. Make them buttons or links when we rebuild.
